# 模型选型评测（碎片处理场景）

用真实负载盲测候选模型，不靠感觉拍板。2026-09-06 首次实战（deepseek-v4-flash vs glm-5.3-flash vs agnes-2.5-flash）。

## 两种模式（先选模式再动手）

| 模式 | 场景 | 工具 | 判据 |
|------|------|------|------|
| **量化选型** | 「哪个模型更适合当 MyPS 后端」——需要决策依据 | `scripts/run_eval.py`（20 题） | 总分 + 必考题专项 |
| **单题对比** | 「把这个问题再问一遍，看看 X 的回答」——用户想看某个模型对某个具体问题怎么答 | `scripts/single_prompt_ab.py` | 人读质性差异（风格/洞察/短板自认） |

**单题对比的姿势（2026-09-23 Grok Bot 对比实测）**：
- **不切主模型**——直接 API 直调，可逆、零风险、不打断正在用的通道。用户说「切换后台再问一遍」时，先判断他要的是「看回答」还是「长期换」：只看回答就直调（还能在同一轮里并排贴出两边回答），别折腾 config
- **喂同等背景**：把 MyPS 的客观情况（部署位置/能力清单/通道/数据存放）写进 system 给对比方，两边信息量一致才比得出模型差异；否则对手只会泛泛而谈，对比失真（本次实测：给了同等背景后 DS 才能给出「外挂+中枢」这类真增量）
- 结果由人读，不打分；**要给出自己的点评**（哪里一致、对手强在哪、哪句不准），不要只转发回答
- 单题对比结论可作为「整段切主模型」的决策输入之一（本次即由用户主观体验 + 直调对比共同支撑 9/23 的路由定案）

## 核心方法

1. **题集 = 真实碎片 + 历史纠正案例**（必考题）。真实碎片测常规能力，历史纠正案例测「会不会在同一个坑翻车」——后者比总分更有决策价值（用户被坑过一次就不想再被坑）。
2. **同一系统提示**（fragment-catcher 核心规则浓缩版）喂所有模型，temperature=0，输出 JSON 限定格式。
3. **评分双维度**：分类标签正确 + 处理动作达标（含陷阱识别）。动作对但分类偏 = 1 分，全对 = 2 分，空/错 = 0 分。

## 必考题清单（从真实用户纠正中提炼，换模型必测）

| 场景 | 题眼 | 翻车表现 |
|------|------|---------|
| 完成信号嵌入查询（「出勤搞完了，帮我查6月7号」） | 先分离完结信号再答查询 | 只答查询漏完结 → 次日简报重复提醒 |
| 行程冲突时间词（修车「下周一、二」撞某省行程） | 解读为行程结束后 | 提醒设进行程内 |
| 忆旧查询（「之前讨论过X吗」） | 术语变体搜索+翻文件，搜不到不许断言没有 | 直接说「没找到」→ 用户失望（答案在深层文档） |
| API key 凭证 | 存配置不写明文 | 分类成知识/日记，泄密风险 |
| 委托型完结（「已交代同事，不需我督促」） | 安排动作完成=完结+注明责任转移 | 建新待办或漏处理 |
| 报销流转（「发票到了」） | 状态更新+清「问发票」提醒 | 当新记账/新待办 |
| 新方向想法（产品化类，涉冻结线） | 守门员：查历史→提醒冻结线→方向候选不建待办 | 直接建待办启动 |

## 2026-09-06 实测结论（三家对比快照）

- 总分（20 题×2 分）：**DeepSeek 34 > GLM 33 > Agnes 31**，接近但性格差异大
- **DeepSeek v4-flash**：零空响应最稳、全部合规，但两个必考题翻车（完成信号、行程冲突）——规则靠提示词硬约束，陷阱识别弱
- **GLM 5.3-flash**：陷阱意识最强（完成信号、忆旧严谨度满分），但思考模式导致 3 次空响应（截断）——真实 Hermes 环境输出上限大，风险低
- **Agnes 2.5-flash**：免费期+原生多模态（能看图，四色块实测通过），但分类图标串号（💬好句/💰记账误用）+忆旧查询直接断言「没找到」——主模型存疑，vision 辅助合适
- 三家在凭证安全、术语勘误、委托完结、守门员冻结线上全部正确

**路由建议**：日常碎片 DeepSeek；深度讨论/晚间总结 GLM-5.3（需实测）；看图 Agnes（免费）。详见 data/knowledge/Personal-AI-OS-概念-20260904.md Model Router 节。

## 视觉/多模态评测（2026-09-06 补充）

选看图模型（auxiliary.vision 候选）时，真实图三类型测试：**票据/单据**（问字段提取：号码/日期/购销方/明细/价税合计/开票人——全对=通过）、**截图**（看版面+语义理解）、**实拍场景**（看细节描述）。判据：关键字段全对 + 语义无歧义。

- 双模型同图对比：`scripts/vision_compare.py <图片路径> [问题]`（Agnes 2.5-flash vs DeepSeek vision-exp；key 从 .env 读；urllib 直发避免大图 base64 超命令行限制）
- 9/6 实测结论：Agnes 票据 OCR 与 DeepSeek 持平、描述更丰富（解读防篡改符号/税收分类编码），截图+实拍全过——切换零降级
- 生成可控测试图（无网络依赖）：纯 Python 手写四色象限 PNG（zlib+struct），模型答对颜色=真能看图，usage.image_tokens>0 佐证
- ⚠️ 大图 base64 走 curl -d 命令行会 Argument list too long——用 Python urllib/aiohttp 直发

## 执行步骤

1. 从 data/ 真实历史抽 15-20 题（含必考题），每条标标准分类+动作要点
2. 写系统提示：8 类定义 + 特殊规则浓缩版 + JSON 输出约束（动作限 30 字内）
3. 跑 scripts/run_eval.py（key 从 ~/.hermes/.env 读，模型参数按需改）
4. 解析结果逐题评分 → 总分表 + 必考题专项表 → 给路由建议

## ⚠️ 踩过的坑

- **max_tokens 太小 + 思考模式 = content 空**：deepseek/glm 默认思考，400 token 会被 reasoning 吃满返回空 content。解法：max_tokens ≥800 + 空响应自动重试 + 能关思考就关（deepseek 支持 `"thinking":{"type":"disabled"}`；glm coding plan 端点该参数无效仍思考）
- **长动作文本撑爆 JSON**：输出约束写「动作限 30 字内」，解析时容错（剥 markdown 代码块、取首尾大括号）
- **线程并行跑三模型**省时间；curl 直连不经 Hermes，避免污染生产配置
- 评测成本极低：60 次调用 ≈ deepseek ¥0.3 / glm 几十积分 / agnes 免费——随便跑
