# SSL 证书续期与验证

> 9/7 实战：某证书站点 zkhjbio.com 同日收到两条阿里云短信（旧证到期提醒 + 新证签发通知）+ 控制台截图三张证书同列，用"先实测再解读"一次闭环。9/6 换证轮（dl-010 → dl-038 预排）已验证周期管理流程。

## 核心心法：先实测线上状态，再解读厂商信息

厂商短信/控制台状态可能滞后、有歧义、与实际情况脱节。收到任何"证书到期/已签发/已部署"信息，**第一步永远是对域名做线上实测**，用事实说话：

```bash
# 网站可达性
timeout 20 curl -sI https://<域名> -o /dev/null -w 'HTTP %{http_code}\n'
# 实际部署的证书详情（subject / issuer / 生效-到期时间）
timeout 20 echo | openssl s_client -connect <域名>:443 -servername <域名> 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

实测结果直接判定：
- notAfter ≈ 新证到期日 → 新证已在跑，到期短信是旧证的，忽略
- 签发时间 = 换证当天 → 签发短信晚于手动部署到达，属通知非动作项

## 阿里云短信/控制台解读对照

| 看到 | 含义 | 动作 |
|------|------|------|
| "云盾证书服务将于 X 到期"（实例 cas_dv-*） | 某张证书的到期提醒（可能是已退役旧证） | 对照 todos 证书待办时间线，确认旧证则忽略 |
| "SSL 证书已签发成功，可下载安装/一键部署" | 新证签发通知 | 实测线上已生效则无需动作；未部署才引导下载安装 |
| 控制台"已部署"列为空（--） | 证书非阿里云一键部署 | **手动装到自建云服务器时阿里云不跟踪——不代表没部署**，以线上实测为准 |
| 控制台多张证书同列（已签发 + 已过期） | 证书代际历史 | 认准"已签发"那张 + 线上实测双确认 |

**关键坑（9/7 实测）**：新证签发成功短信可能比手动部署动作晚到一天（9/6 已手动部署完成，9/7 才收到通知）。收到签发短信别急着引导用户下载安装——先实测，已生效就一句话安抚"短信晚到，无需操作"。

## 换证完结 → 下轮预排（防空白期）

换证报备时（用户说"换完了/签发了"）：
1. 完结旧轮 deadline，text 追加新证到期日
2. 立即预建下轮：deadline = 到期日前 2~3 天（留缓冲，不用到期日当天）
3. 建提前提醒 Cron：提前约一周（签发/审核要时间）
4. text 保留完整周期时间线（旧到期日 → 新到期日）与**部署方式**（手动 or 一键），下轮提醒直接带上下文
5. 回复一句话报下轮截止 + 提醒时间

> ⚠️ 阿里云免费 DV 证书有效期短（实测签发 9/6 → 到期 12/5，仅 ~3 个月），续期频率远高于一年期证书——每轮完结当场预排下轮是唯一不漏的机制。到期/签发两条短信常在相邻两天到达，容易误读为两个独立事项。

## 陷阱
- 短信抬头是阿里云账号实名（如"胡新华"），域名在正文——先核对是哪张证书哪个域再下结论
- 旧证退役后阿里云仍发到期提醒（到期前 1 天那种），别被带节奏去续费已废的实例
- 免费 DV 单域名证书的域名覆盖范围要看清（单域 or 含 www 一并覆盖），确认换的是同一张
